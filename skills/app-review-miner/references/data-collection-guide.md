# 데이터 수집 가이드

공개적으로 접근 가능한 정보와 사용자가 제공한 데이터만 사용한다. 약관 위반 가능성이 있으면 무리해서 수집하지 말고 실패 사유와 대체 입력 형식을 안내한다.

## 입력 우선순위

가장 좋은 입력:

1. 실제 리뷰 CSV/JSON
2. 사용자가 복사해 붙여넣은 리뷰 원문
3. 앱스토어/구글플레이 링크
4. 앱 이름 + 국가/플랫폼
5. 경쟁 앱 목록
6. 리뷰 화면 스크린샷

## 리뷰 데이터 필드

가능하면 아래 필드를 인식한다.

- app_name
- platform
- country
- rating
- date
- review_title
- review_body
- app_version
- developer_reply
- helpful_count
- language

## 데이터가 적을 때 처리

- 리뷰가 10개 미만이면 정량 분석처럼 말하지 않는다.
- 리뷰가 30개 미만이면 "초기 방향성"으로 표현한다.
- 리뷰가 100개 이상이면 반복 패턴과 우선순위를 더 강하게 제시한다.
- 리뷰가 별점별로 편향되어 있으면 편향을 명시한다.
- 최신 리뷰와 오래된 리뷰를 구분한다.
- 업데이트 전후 불만이 달라질 수 있음을 명시한다.

## 앱스토어/구글플레이 주의사항

- 공개적으로 접근 가능한 정보만 사용한다.
- 약관 위반 가능성이 있으면 무리해서 수집하지 않는다.
- 사용자가 제공한 데이터가 가장 안전하다.
- 수집이 실패하면 실패 사유를 표시하고, 사용자가 붙여넣을 수 있는 데이터 형식을 안내한다.
- 개인정보는 익명화한다.

## 안전 수집 규칙

- 로그인 우회, 캡차 우회, 유료 데이터베이스 우회, 비공개 리뷰 접근을 시도하지 않는다.
- 리뷰 작성자 이름, 계정명, 식별 가능한 개인정보를 보고서에 남기지 않는다.
- 앱 이름만 있는 경우에도 검색 가능성을 먼저 확인하되 공식 리뷰 확인 실패 여부를 명확히 적는다.
- 스크린샷 입력은 OCR 또는 시각 판독으로 가능한 범위만 사용하고 판독 불확실성을 표시한다.
