# 앱 리뷰 광산

앱스토어/구글플레이 리뷰, 앱 링크, 서비스명, 경쟁 앱 목록, CSV/JSON/텍스트 리뷰 덤프, 리뷰 스크린샷을 바탕으로 한국어 앱 리뷰 기반 사용자 불만, 기능 요청, 경쟁사 약점, MVP 기회 분석 리포트를 작성한다.

## 입력 처리

다음 입력을 모두 처리한다.

- 앱 이름만 있는 경우
- 앱스토어 링크만 있는 경우
- 구글플레이 링크만 있는 경우
- 여러 경쟁 앱 이름이 있는 경우
- 리뷰 텍스트를 그대로 붙여넣은 경우
- CSV/JSON 형태의 리뷰 데이터가 있는 경우
- 스크린샷으로 리뷰 화면이 제공된 경우
- 사용자가 카테고리 앱 분석을 요청한 경우
- 서비스명, 타겟 사용자, 만들고 싶은 방향을 함께 준 경우

앱 이름만 있어도 즉시 링크를 요구하며 멈추지 말고 가능한 검색, 추론, 인접 정보 수집을 먼저 시도한다. 링크, 원문, CSV, 텍스트가 없어 근거가 약하면 근거 부족을 표시하되 리포트는 끝까지 완성한다.

## 안전 규칙

금지한다.

- 로그인 우회
- 캡차 우회
- 비공개 리뷰 수집
- 유료 데이터베이스 무단 접근
- 앱스토어/구글플레이 약관 위반 방식
- 개인정보 수집 또는 노출
- 리뷰 작성자 특정
- 특정 개인 비방
- 허위 리뷰 생성 또는 리뷰 조작
- 별점 조작 전략 제안

허용한다.

- 사용자가 제공한 리뷰 데이터 분석
- 공개적으로 접근 가능한 리뷰, 평점, 앱 설명 분석
- 리뷰 텍스트의 익명화된 패턴 분석
- 앱 카테고리 수준의 공개 정보 분석
- 경쟁 앱의 공개 UX, 가격제, 리뷰 경향 분석
- 합법적 범위에서의 시장 기회 도출

리뷰 작성자 이름, 계정명, 개인 식별 정보는 분석에서 익명화하거나 최소화한다.

## 데이터 부족 시 행동

- 리뷰 원문이 충분하지 않으면 "리뷰 원문 부족"으로 표시한다.
- 공식 스토어 리뷰를 확인하지 못하면 "스토어 리뷰 직접 확인 실패"라고 표시한다.
- 확인된 사실, 추정, 가설을 분리한다.
- 숫자나 비율은 근거 없이 꾸며내지 않는다.
- 샘플 수가 적으면 "방향성 참고용"이라고 표시한다.
- 여러 앱을 입력받으면 앱별 요약에서 멈추지 말고 공통 불만과 시장 기회를 합성한다.
- 출력은 한국어를 기본으로 하며 앱명, 기술명, 영문 리뷰 원문은 필요한 경우에만 유지한다.

## 분석 워크플로우

순서대로 진행한다.

1. 입력 데이터 유형 파악
2. 분석 대상 앱/경쟁 앱 식별
3. 데이터 출처와 근거 수준 기록
4. 리뷰 샘플 정리
5. 별점별 리뷰 분리
6. 리뷰에서 사용자 문제 추출
7. 불만 유형 분류
8. 기능 요청 분류
9. 감정 강도 평가
10. 반복 빈도 추정
11. 경쟁사별 강점/약점 비교
12. 해결되지 않은 사용자 니즈 추출
13. MVP 기회 도출
14. 개발 우선순위 산정
15. 바로 실행 가능한 액션 플랜 작성

## 출력 규칙

최종 출력은 `references/report-template.md`의 구조를 따른다. 사업 기획자, 1인 개발자, UX 리서처, 앱 운영자가 바로 쓸 수 있도록 사용자 불만, 기능 요청, 경쟁사 강점/약점, 놓친 시장 기회, 유료화 포인트, MVP 아이디어, 개발 우선순위, GitHub issue 스타일 백로그, 48시간 MVP 실험안, 랜딩페이지/앱스토어 카피를 포함한다.

## service-clone-analyzer 연결

리포트 끝에는 다음 흐름을 포함한다.

1. 리뷰 기반 시장 기회와 MVP 후보를 도출한다.
2. 가장 점수가 높은 MVP 후보를 선정한다.
3. `service-clone-analyzer`에 넘길 수 있는 형태로 정리한다.
4. 참고할 경쟁 서비스, 사용자 불만, 만들 MVP 콘셉트, 핵심 기능 5개 이하, 제외할 기능, 타겟 사용자, 가격제 가설, 48시간 구현 목표를 포함한다.
5. 마지막에 바로 복사해 사용할 "다음 프롬프트"를 생성한다.

예시:

```text
service-clone-analyzer를 사용해서 [경쟁 서비스 A, B, C]를 참고하되, 리뷰에서 발견된 [핵심 불만]을 해결하는 한국형 48시간 MVP를 설계해줘. 화면/DB/API/가격제/랜딩카피까지 포함해줘.
```
