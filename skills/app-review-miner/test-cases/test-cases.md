# 테스트 케이스

## 테스트 1. 서비스명만 있는 경우

입력:

```text
픽크닉 리뷰 분석해서 사용자 불만과 만들 만한 MVP 뽑아줘.
```

기대 결과:

- 링크 요구로 멈추지 않는다.
- 근거 수준을 표시한다.
- 리뷰 원문 부족 시 명시한다.
- 사용자 불만/기능 요청/MVP 기회 섹션이 포함된다.

## 테스트 2. 리뷰 원문이 있는 경우

입력:

```text
리뷰 10~20개 샘플 텍스트
```

기대 결과:

- 리뷰를 분류한다.
- 반복 불만을 찾는다.
- 별점별 인사이트를 작성한다.
- 백로그로 변환한다.

## 테스트 3. 경쟁 앱 여러 개

입력:

```text
딸깍, 릴리스AI, 리캐스트 리뷰를 비교해서 한국 SaaS 운영자용 MVP 기회 뽑아줘.
```

기대 결과:

- 각 앱별 강점/약점 비교표가 있다.
- 공통 불만을 추출한다.
- 하나의 MVP 후보로 합성한다.
- 최종 추천 MVP와 48시간 실험 계획이 포함된다.

## 테스트 4. 낮은 별점 중심 분석

입력:

```text
이 앱의 1점 리뷰만 보고 왜 삭제당하는지 분석해줘.
```

기대 결과:

- 치명 문제 중심으로 분석한다.
- 감정 강도와 영향도를 평가한다.
- 빠른 개선 백로그를 만든다.

## 테스트 5. 리뷰 데이터 부족

입력:

```text
이 앱 리뷰 별로 없는데 그래도 MVP 기회 뽑아줘.
```

기대 결과:

- 데이터 부족을 명시한다.
- 정량처럼 과장하지 않는다.
- 가설 기반 분석으로 표시한다.
- 추가로 필요한 데이터를 안내한다.
