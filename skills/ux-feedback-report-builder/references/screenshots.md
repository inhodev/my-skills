# 화면 캡처: 추출 → 선별 → 크롭 → 배치 → 빨간 네모

캡처는 이 보고서의 근거다. 캡처가 흐리거나, 엉뚱한 장면이거나, 마크가 어긋나면 보고서 전체의 신뢰가 무너진다. 이 파일의 규칙은 전부 실제로 지적받은 것들이다.

## 1. 추출

- **원본 MP4에서 ffmpeg로 직접 추출한다.** 사전 추출된 `frames_5s/`, `evidence_frames/`는 절반 해상도인 경우가 흔하다(원본 1080×2400 → 추출본 540×1200). 매번 `ffprobe`로 원본 해상도를 확인하고, 쓰려는 파일의 해상도와 대조한다.
- 그때만 발생한 오류 장면은 반드시 영상에서. 상시 화면(대시보드, 설정)은 앱에서 직접 찍는 것이 화질이 좋다.
- 특정 시각 프레임 추출:
  ```bash
  ffmpeg -ss 00:12:34.5 -i input.mp4 -frames:v 1 -q:v 2 out.jpg
  ```
- 구간 후보를 시트로 뽑기 (선별용):
  ```bash
  ffmpeg -ss 00:12:00 -t 60 -i input.mp4 -vf "fps=1,scale=iw/3:-1,tile=10x6" -q:v 3 sheet.jpg
  ```
- 세로 녹화가 기본. 가로로 녹화된 폰 영상은 폰 영역이 폭 500px밖에 안 된다. 테스터 모집 시 **세로 화면 녹화**를 안내한다. 카카오 인앱 등 필러박스 영상은 폰 영역만 크롭한다.

## 2. 선별

- **프레임 번호로 고르지 않는다.** 번호 오독으로 엉뚱한 화면이 들어간 적이 있다. 시트를 만들어 눈으로 확인한 뒤 고른다.
- 시트 육안으로 끝내지 않는다. 핵심 요소(오류 배너, 강조 버튼, 빈 상태 안내)가 실제로 그 프레임에 있는지 `scripts/find_color_band.py`로 **픽셀 색으로 검증**한다. 시트 축소본에서 배너가 있는 줄 알고 넣었는데 없던 적이 있다.
- 개인정보 프레임 금지: 사진첩·갤러리, 실명, 이메일, 계정 정보, 브라우저 탭·북마크에 보이는 학교·회사명, 카톡 알림.
- 같은 장면을 두 번 넣지 않는다(다른 참가자의 같은 화면은 허용, 캡션으로 구분).

## 3. 크롭

원칙: **앱(서비스) 화면만 남기고 기기·브라우저 UI는 잘라낸다. 단 앱 자체 하단 탭바는 남긴다.**
예외: 브라우저 자체가 증거인 장면(보안 경고, 주소창 오류)은 브라우저 UI를 유지한다.

### 모바일 웹 실측 크롭값 (y 픽셀, 상단~하단)

| 기기/브라우저 | 원본 | 크롭 y | 비고 |
|---|---|---|---|
| iOS Safari | 880~884 × 1920 | 120 ~ 1755 | 상태바+주소창 / 하단 툴바 제거 |
| iOS Safari 주소 상단형 | 1290 × 2796 | 255 ~ 2565 | |
| Android Chrome | 1080 × 2400 | 215 ~ 2272 | |
| 카카오 인앱 (필러박스) | 폰 영역 | 상단 헤더 +140 | 좌우도 폰 영역만 |

값은 새 프로젝트마다 한 프레임에서 실측해 조정한다. `scripts/crop_frames.py --preset` 으로 적용하고 `--probe`로 경계선을 그린 확인 이미지를 먼저 본다.

### 데스크톱

- 브라우저 탭·북마크바·주소창(y 0~145 부근)과 하단 작업표시줄(y 1040 이후)을 잘라낸다. y 145 ~ 1026 이 안전(1040이면 작업표시줄이 살짝 남는다).
- 콘텐츠 열만 잘라 쓰는 경우 좌우도 크롭한다. 넓은 화면의 여백이 논점일 때만 전체 폭을 남긴다.

### 크롭 함정

- PIL `crop()`은 이미지보다 큰 박스를 주면 **검정 패딩**을 만든다. 결과에 검정 띠가 보이면 크롭 좌표가 아니라 원본 해상도를 의심한다(절반 해상도 파일).
- 크롭을 바꾸면 그 이미지의 모든 빨간 네모 좌표가 무효화된다. **크롭 확정 → 마크 산출** 순서.
- 마크 대상이 크롭 경계에 걸려 있으면 마크를 키우지 말고 **크롭을 넓힌다**(말풍선이 잘린 사례).

## 4. 크기와 배치

### 폭 기준 (한 행에 몇 장이냐로 고정)

| 행 구성 | 카드 폭 | 이미지 세로 `--ih` (세로 폰 기준) |
|---|---|---|
| 1장 | 62mm | 126mm |
| 2장 | 54mm | 109mm |
| 3장 | 46mm | 92mm |
| 인용 옆 1장 | 40~44mm | 84mm |
| 관찰 박스 옆 1장(가로형) | 계산 | 58mm |

- 이보다 작으면 "너무 작다"는 지적을 받는다. 캡처를 늘려야 하면 폭을 줄이지 말고 **캡처 전용 행**(`.shots.only`, 가운데 정렬)으로 분리하고 인용·박스는 아래 행으로.
- 세로 폰 캡처는 높이 = 폭 × 2.15 라 폭 62mm면 세로 133mm. A4 본문 267mm에서 2장 이상 세로로 쌓기 어렵다. 더 키우려면 화면 일부만 크롭해야 하는데 **전체 화면 유지가 원칙**이다.

### 정렬 (테스터마다 화면비가 다르다)

- 화면비 2.15~2.31 사이로 달라서 같은 폭이면 세로가 최대 7% 어긋난다.
- 행마다 `--ih`를 고정하고 `img{height:var(--ih);width:auto}`, `.shots{align-items:stretch}`, `.cap{display:flex;flex-direction:column;align-items:center}`. 카드 상·하단이 맞는다.
- `--ih` = (카드폭 − 3.2mm) × 2.15. 폭 46/54/60/62 → 92/109/122/126mm.

### 행 폭 초과 = 전 페이지 축소

- 한 행의 카드 폭 합계 + gap이 본문 폭(A4 210 − 좌우 15 = **180mm**)을 넘으면 Chrome이 **모든 페이지를 일괄 축소**한다. 증상: 전 페이지에 얇은 흰 테두리, 글자가 미세하게 작아짐.
- 가로형 캡처(데스크톱)는 폭 = `--ih` ÷ (세로/가로) 로 계산해 행을 짠다. 예: 1280×880 크롭, ih 58mm → 폭 84mm. 두 장이면 이미 168 + gap.
- `scripts/qa_pages.py`가 축소 증상(전 페이지 동일 테두리)을 경고한다.

### 배치 규칙

- 이미지를 페이지 가운데 홀로 띄우지 않는다. 단독 이미지 = 왼쪽 정렬 + 오른쪽 관찰 정리 박스.
- 캡처 행을 오른쪽 끝까지 꽉 채우지 않는다(플러시 금지). 줄여서 중앙 정렬하거나 여유를 남긴다.
- 관찰 박스는 내용만큼만. `height:100%` 금지.
- 캡처 옆 인용 박스는 `.qs{flex:1}` + `.q{flex:1}`로 세로를 나눠 갖는다.

## 5. 빨간 네모 (마크)

### 그리기 규칙

- **테두리만.** `border:2px solid var(--red); border-radius:7px; box-shadow:0 0 0 1.5px rgba(255,255,255,.55)`.
- 화면 위에 **글자·라벨·화살표·번호 절대 금지.** 알약형 라벨을 화면 위에 띄웠다가 앱 콘텐츠를 가려서 크게 지적받았다. 설명은 캡션에, 강조는 캡션의 빨간 글씨.
- 한 이미지에 마크 1~2개. 대상 요소만 감싼다. 무관한 탭·안내문까지 넓히지 않는다.
- 캡션의 빨간 강조가 이미 설명하는 장면(빈 화면 전체, 잘린 차트 전체)은 네모를 **생략**한다. 남발하면 마크의 의미가 없어진다.
- 마크는 HTML에서 `.iw` 안에 `<div class="mk" style="left:x%;top:y%;width:w%;height:h%">`로 그린다. 좌표는 크롭된 이미지 기준 %.

### 좌표 산출 규칙 ("대부분 뒤틀려 있어" 지적 이후)

1. **눈대중 % 금지.**
2. 색이 있는 대상(오류 배너, 브랜드색 버튼, 분홍/빨강 경고)은 `scripts/find_color_band.py`로 **픽셀 색 감지**해 자동 산출한다.
   ```bash
   python3 find_color_band.py img/m_p2_fail.jpg --preset pink      # 분홍 배너
   python3 find_color_band.py img/x.jpg --rgb 91,63,212 --tol 40     # 브랜드 보라
   python3 find_color_band.py img/x.jpg --preset pink --axis both --pad 1.5
   ```
   출력은 `[x%, y%, w%, h%]`. 그대로 `marks.json`에 넣는다.
3. 색으로 못 잡는 대상(텍스트, 빈 영역)은 일단 추정값을 `marks.json`에 넣고, `scripts/mark_review_sheet.py`로 **실제로 그린 시트**를 만들어 전수 확인 후 보정한다. 보정 → 다시 시트 → 확인. 확인 없이 납품하지 않는다.
4. `marks.json` 형식: `{"이미지파일명(확장자 제외)": [[x,y,w,h], ...]}` (단위 %). HTML의 `.mk` 인라인 스타일과 동기화한다(스크립트가 `--apply`로 HTML에 써넣는다).

### 검수

- `mark_review_sheet.py`는 마크가 있는 이미지만 모아 마크를 그린 시트를 만든다. 이 시트를 눈으로 본다: 대상이 네모 안에 다 들어왔는가, 여백이 과하지 않은가, 경계에 잘리지 않았는가.
- 최종 PDF의 `qa_pages.py` 시트에서도 한 번 더 본다(HTML 인라인 좌표와 JSON이 어긋났을 수 있다).

## 6. 파일 이름

- `img/` 안 이름은 `{기기}_{참가자}_{장면}.jpg`: `m_p2_fail.jpg`(모바일, 참가자 2, 실패), `d_p7_cal.jpg`(데스크톱, 참가자 7, 캘린더).
- 크롭 전 원본은 `raw/`에 같은 이름으로 둔다. 크롭을 다시 할 수 있어야 한다.
