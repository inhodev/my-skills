# 지적·결정 로그 (날짜순)

클라이언트와 운영자가 실제로 지적한 것과 그 자리에서 확정한 규칙의 원문 기록.
규칙의 "왜"가 궁금하면 여기를 본다. 새 지적이 생기면 맨 아래에 날짜와 함께 추가한다.

---

## 2026-05 ~ 06 · 첫 납품 4건 (38p, 20p, 20p, 30p)

- ChatGPT 채팅에서 PDF 만들고 수작업 편집 → 시간이 너무 많이 듦. 자동화 필요성 확인.
- High/Medium 심각도 라벨과 "전환 가능성 60/100" 점수를 넣었다가 **"AI티 나고 근거 없다"**는 이유로 의도적으로 뺌. 되살리지 말 것. 대신 "8명 중 5명" 인원 표현.
- 카피 개선안은 AI 초안 + 운영자 토론/큐레이션으로만.
- 30p 납품본(꽃갈피)이 구조·톤의 기준이 됨: 질문형 제목, 흰 카드 + 점선 리스트, 연한 배경 인용, 조사목적/방법/참가자 → 요약 → 주제별 → 참가자별 → 먼저 고칠 5가지 → 결론.

## 2026-07-29 · 함께하는건강 20p 제작 중

- **캡처 위 알약형 라벨 → 앱 콘텐츠를 가림 → 크게 지적.** "빨간 네모(테두리)만 그리고 설명 글자는 절대 화면 위에 얹지 말 것." 설명은 캡션에, 강조는 캡션 안 빨간 글씨.
- 프레임 번호로 골랐다가 엉뚱한 화면이 들어감 → 시트로 뽑아 눈으로 확인 후 선택.
- 기존 `frames_5s`가 원본의 절반 해상도(1080×2400 → 540×1200) → 원본 MP4에서 ffmpeg로 재추출.
- 한 테스터만 가로 녹화(1920×1080)라 폰 화면 폭 500px → 앞으로 "세로 화면 녹화" 안내.
- **여백**: 꽃갈피의 넉넉한 여백을 그대로 따랐더니 "고객들도 꽉 찬 보고서를 더 좋아함" → 하단 여백 평균 29% 이하, 40% 초과 0개 기준 확정. 채울 때는 없는 말 만들지 말고 미사용 캡처·실제 관찰·인용으로만.
- **캡처 크기**: 작게 넣었다가 "너무 작다" → 1장 62mm / 2장 54mm / 3장 46mm 확정. 늘릴 때는 폭 줄이지 말고 캡처 전용 행으로 분리. 전체 화면 유지 원칙(일부 크롭으로 키우기 금지).
- **정렬**: 테스터마다 화면비 달라(2.151~2.310) 카드 상·하단 안 맞음 → 행마다 `--ih` 고정, `img{height:var(--ih);width:auto}`.
- 시각적 AI slop 지적: 영문 eyebrow 라벨(EXECUTIVE SUMMARY), 다크 네이비 박스, 표지 배너·폰 목업, "FEEDBACK LAB" 자체 브랜딩, 격언조 문장 → 전부 금지.

## 2026-07-30 · 함께하는건강 납품 직전

- AI티 제거 추가 규칙:
  1. 캡션 구분자 대시(—) 금지 → 콜론(:)
  2. 자료 인벤토리 나열("영상 5본, 전사 5건, 프레임 747장") 금지 → 행위 서술("화면을 5초마다 잘라 700장 넘게 대조했다")
  3. 조사 개요에 총 녹화 분량·평균 넣지 말 것, 본문에 "62분 12초" 같은 녹화 시간 금지
  4. 리스트 명사형 종결("~설정", "~수집") 금지 → 하는 일 서술("~고릅니다")
  5. 참가자 실제 발언 절대 다듬지 말 것
  6. 플랫폼 표기 "iOS 3명 · iOS TestFlight 1명 · Android 1명" (TestFlight 따로 셈)
  7. 조사 일정은 사용자 지정 표기 그대로
- 참가자 A~E 익명, 실명·연령·성별 비공개, 인용에 타임스탬프 없음.
- `보고서_작성_표준.md` 첫 작성. 이후 프로젝트는 이 문서 + report_source 복사로 시작.

- **모바일 웹 크롭 규칙** (사용자 지시): 상단 상태바·주소창, 하단 브라우저 컨트롤 잘라내고 **앱 자체 하단 탭바는 남길 것**. 예외는 브라우저가 증거인 장면. 실측값 iOS Safari 880×1920 y120~1755 / iOS 1290×2796 y255~2565 / Android 1080×2400 y215~2272 / 카카오 인앱 상단 +140. 데스크톱 y145~1026.
- **"대부분 뒤틀려 있어"** (빨간 마크 지적): 눈대중 % 금지. 색 있는 대상은 픽셀 색 감지(분홍 배너: R−B>7 & R>225 행 스캔)로 자동 산출. 수동 대상은 마크를 실제로 그린 검수 시트로 전수 확인 후 보정. 크롭 바꾸면 좌표 전부 무효 → 크롭 확정 후 마크. 경계에 잘린 대상은 크롭을 넓힐 것.

- **캡처 행 폭 합계가 180mm 초과 → Chrome이 전 페이지를 일괄 축소** (모든 페이지에 흰 테두리 증상). 가로형 캡처 폭 = ih ÷ 화면비로 계산.
