# 글쓰기 규칙: AI티 없애기

이 보고서의 독자는 서비스를 만든 사람이다. 그들은 "컨설팅 보고서 흉내"를 바로 알아본다.
목표는 **옆에서 테스트를 다 지켜본 사람이 담백하게 들려주는 말투**다.

## 1. 기본 자세

- 모든 문장은 관찰(누가, 어떤 화면에서, 무엇을 했고, 뭐라고 말했나)에서 출발한다.
- 평가어("좋다", "아쉽다", "직관적이다") 대신 일어난 일을 쓴다.
- 우선순위는 인원수로만. "8명 중 5명", "세 명(B·D·G)". 심각도 라벨·점수·% 금지.
- 지어내지 않는다. 분석 md에 없는 관찰·인용은 쓰지 않는다. 여백을 채울 때도 마찬가지.

## 2. 금지표 (지적받은 것들)

| 금지 | 대신 | 왜 |
|---|---|---|
| 대시(—, –, -를 문장 구분자로) | 콜론(:) 또는 괄호, 문장 분리 | AI 문체의 대표 흔적. 캡션·본문 전부 |
| 영문 라벨 (EXECUTIVE SUMMARY, KEY FINDINGS, INSIGHT) | 한글 소제목 | 컨설팅 템플릿 티 |
| 격언조 ("신뢰는 첫 번째 기능입니다", "관문이 좁고 무기는 숨어 있다") | 관찰 근거 평서문 | 멋 부린 문장은 근거가 없어 보임 |
| 비유적 압축 결론 ("관문을 넓히고 무기를 꺼내는 것") | "먼저 ~하고, 다음으로 ~하고, 마지막으로 ~한다" | 결론부에서 특히 지적됨 |
| 자료 인벤토리 ("영상 5본, 전사 5건, 프레임 747장") | 행위 서술 ("화면을 5초마다 잘라 700장 넘게 대조했습니다") | 숫자 나열은 기계 보고 느낌 |
| 녹화 시간 수치 (62분 12초, 평균 40분) | 언급하지 않음 | 불필요한 정밀도 |
| 타임스탬프 (03:12, [12:40]) | 인용에 "참가자 B"만 | 본문에서 정밀도 과시로 보임 |
| 명사형 종결 리스트 ("~설정", "~수집", "~확인") | 하는 일 서술 ("~고릅니다", "~써봅니다") | 조사 방법 목록에서 지적 |
| 가운뎃점(·) 나열 남발 ("A·B·C·D·E를 확인") | 문장으로 풀거나 2~3개까지만 | 결론부에서 지적 |
| 짧은 경구형 맺음 인용 | 4~5문장 평이한 마무리 | "AI 명언 생성기" 느낌 |
| 부정형 한계 진술 ("지불 의향은 드러나 있지 않다") | "첫 사용의 기록으로 읽어 달라, 장기 경험은 다음 테스트에서" | 한계 박스는 다음 의뢰로 잇는 자리 |
| 조사 목적에 약점 기능 미리 언급 | 핵심 경험이 자연스러운지 확인, 로 중립 서술 | 결과를 목적에 심어놓은 것처럼 보임 |
| "화면을 녹화했다" 언급 | 참가자가 한 행동만 서술 | 방법론 설명 과잉 |
| 다크 박스, 배너, 폰 목업, 자체 브랜딩 로고 | 흰 카드, 담백한 구성 | 시각적 AI slop |

## 3. 인용 규칙

- **참가자 발언은 원문 그대로.** 문법이 어색해도, 말이 끊겨도, 반복이 있어도 다듬지 않는다. 다듬는 순간 진짜 발언이 아니게 된다.
- 표기: 인용 박스 안 마지막 줄에 `참가자 B`. 참가자 페이지 안에서는 표기 생략 가능.
- 뜻이 확실하지 않은 전사(음성 불명확)는 싣지 않는다. 억지로 복원하지 않는다.
- 회사·서비스 이름 오전사는 화면과 대조해 바로잡는다(이건 "다듬기"가 아니라 오류 수정).
- 한 인용을 여러 주제 페이지에서 반복하지 않는다. 참가자 페이지에서의 재사용은 허용.
- 인용 길이는 1~3문장. 긴 발언은 핵심 문장만 자르되, 자른 티가 나지 않도록 문장 경계에서 자른다. 말줄임표(…)로 잇지 않는다.

## 4. 문장 톤 예시

나쁜 예 → 좋은 예

- "온보딩 경험이 직관적이지 않았다" → "가입을 마치고 나면 아무것도 없는 빈 대시보드가 기다리고 있었습니다"
- "에러 핸들링이 미흡함(High)" → "회원가입이 실패했는데 이유와 비밀번호 규칙이 표시되지 않음"
- "AI 기능의 발견성 개선 필요" → "가장 강한 AI 기능이 구독 안내에서만 보이고 실제 화면에서는 숨어 있음"
- "여덟 개의 기록을 겹쳐 보면 제품의 모양이 선명해집니다. 개념은 검증됐고, 관문이 좁고, 무기는 숨어 있습니다." → "고칠 순서는 분명합니다. 먼저 링크 분석이 어떤 공고에서도 실패하지 않게 만들고, 다음으로 분석 결과에 마감일과 제출 서류 정보를 채우고, 마지막으로 AI 자기소개서와 모의면접을 사용자가 바로 볼 수 있는 곳으로 옮기는 것입니다."

## 5. 캡션

- 구분자는 콜론: "회원가입 화면: 실패했다는 메시지만 있고 이유가 없습니다"
- 강조할 단어만 `<b>`(빨간). 한 캡션에 강조 1~2개.
- 캡션은 화면 설명 + 봐야 할 점. 해석은 옆 관찰 박스로.
- 길이 1~2줄. 넘치면 카드가 어긋난다.

## 6. 인원 표기

- 클라이언트가 원하는 표지 숫자(예: 모집 10명)와 실제 분석 참가자 수(예: 8명 A~H)가 다르면, 개요에서 "테스트 참가 10명, 기록 상세 분석 8명(참가자 A ~ H)"로 잇는다. 본문의 "N명 중 M명"은 분석 참가자 수 기준.
- 플랫폼은 집계로만. 개별 참가자의 기기 모델·OS 버전은 쓰지 않는다.
- 조사 일정은 사용자가 지정한 표기 그대로(예: 2026.08.11 - 14).

## 7. 특별 프레이밍

- 어떤 기능을 처음부터 끝까지 집중해서 판 참가자가 있으면 요약·강점·참가자 페이지에서 "처음부터 끝까지 집중 테스트한 참가자"로 특별하게 짚는다. 그 사람의 검증이 서비스의 강점 근거가 된다.
- 유일하게 어떤 행동을 한 참가자(문의를 남김, 외부에서 검증함)는 그 행동 자체를 관찰로 살린다.

## 8. 자동 검사

`scripts/lint_text.py report.html`이 위 금지표의 기계 검출 가능한 항목을 잡는다. 통과했다고 끝이 아니다. 격언조·비유·명사형 종결은 사람이 읽어야 잡힌다. 최종본은 처음부터 끝까지 한 번 소리 내어 읽듯 훑는다.
