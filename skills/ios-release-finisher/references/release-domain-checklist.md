## 1. 상태 모델

모든 항목을 다음 중 하나로 기록한다.

| 상태 | 의미 | 다음 행동 |
|---|---|---|
| `VERIFIED` | 파일, 명령 결과, 실행 화면, Apple 응답으로 확인 | 증거를 남기고 진행 |
| `DRAFTED` | 사실 근거로 안전한 초안을 작성 | 승인 전까지 초안 유지 |
| `DEFERRED_INPUT` | 지금 없어도 다른 작업을 계속할 수 있는 사용자 값 | 마지막에 한 번만 요청 |
| `EXTERNAL_BLOCK` | 로그인, 2FA, 계정 권한, 계약 등 외부 행동 필요 | 해당 분기만 보류 |
| `RELEASE_BLOCK` | 그대로 제출하면 실패·위반 가능성이 높은 결함 | 안전한 수정 권한이 있으면 수정 |
| `OPTIONAL` | 출시를 막지는 않는 개선 | 핵심 작업 후 처리 |

## 2. 14개 출시 영역

### 앱 신원

- 정확한 프로젝트 루트, 플랫폼, 앱 이름
- main target와 extension의 Bundle ID
- SKU, Apple ID, 기본 언어
- marketing version, build number
- Team ID, signing 방식, capabilities
- App Store Connect 기존 레코드와 exact Bundle ID 일치

### 상품 페이지 문구

- 이름 2~30자, 부제목 30자 이하
- 설명 4,000자 이하, 키워드 100바이트 이하
- 프로모션 문구 170자 이하
- 지원 URL, 개인정보 처리방침 URL, 선택적 마케팅 URL
- 저작권, 카테고리, 콘텐츠 권리
- 업데이트면 새로운 기능 문구
- 과장·거짓·경쟁사명·키워드 남발 금지

### 스토어 이미지

- iPhone 스크린샷 1~10장
- iPad 지원 시 13인치 이미지
- 실제 UI와 현재 빌드 일치
- 언어별 이미지와 대체 노출 확인
- 개인정보·테스트 계정·저작권 침해 요소 제거
- 미리보기 영상은 선택이며 실제 앱 사용 장면으로 구성

### 현지화

- 앱 내부 지원 언어와 App Store 현지화를 별도로 확인
- 이름·부제목·설명·키워드·URL·이미지의 locale 세트 정합성
- 직역 금지, 현지 표현과 검색 의도 반영
- 기본 언어 fallback으로 잘못된 이미지가 노출되지 않는지 확인

### 연령 등급

- 광고, 채팅, UGC, 무제한 웹 접근
- 보호자 통제, 연령 확인
- 욕설, 공포, 선정성, 성적 콘텐츠, 약물, 무기, 폭력
- 건강·의료 정보
- 경연, 모의 도박, 실제 도박, 루트박스
- Made for Kids, 상향 override, 한국 override
- 후보 답은 근거와 함께 작성하고 의미 판단은 승인받기

### 개인정보

- 코드, SDK, 서버, DB의 실제 데이터 흐름
- App Privacy 데이터 유형·목적·연결·추적
- PrivacyInfo.xcprivacy와 Required Reason API
- ATT, IDFA, tracking domain
- 권한 목적 문구와 거부 시 대체 동작
- 보유·파기·삭제·정정·동의 철회
- 제3자 제공, 처리 위탁, 국외 이전
- 처리방침, 앱 내부 화면, App Privacy 응답의 일치

### 법률 문서

- 개인정보 처리방침
- 회원·구독·UGC·AI 기능이면 이용약관 필요성 판단
- 커뮤니티 운영정책, 신고·차단·삭제 기준
- 구독·환불·해지·콘텐츠 권리
- 저작권, 상표, 이미지·음악·영상 라이선스
- 정책 문구만 만들지 말고 실제 기능과 운영 절차 확인

### 국가별 규정

- 한국 개발자 식별정보, 사업자등록번호, 세금 정보
- 한국 게임 GRAC 또는 위치기반서비스 신고 필요성
- EU DSA trader/non-trader와 공개 연락처
- EU·EEA·영국·미국 의료기기 선언
- 중국 ICP, 게임·출판·종교·뉴스 허가
- 베트남 게임 라이선스
- 출시 국가를 줄이면 피할 수 있는 규정과 사업상 영향 분리

### 수출규정

- 암호화 사용, 표준·비표준·자체·제3자 암호화 구분
- 면제 여부와 `ITSAppUsesNonExemptEncryption`
- 프랑스 또는 미국 수출 문서 필요성
- App Encryption Declaration과 문서 승인 상태

### 가격과 배포

- 무료·유료, 기본 국가, 가격점, 일정
- 175개 storefront 중 출시 범위
- 공개, 비공개 Custom App, unlisted
- 사전 주문, 교육 할인, 세금 카테고리
- 수동·자동·날짜 지정 출시
- 업데이트 단계적 배포와 평점 초기화 여부

### 결제와 구독

- 디지털 상품은 IAP 사용
- 실물 상품·서비스 결제와 구분
- Paid Apps Agreement, 세금, 은행
- Product ID, 유형, 가격, 국가, 현지화
- 심사 메모와 심사용 스크린샷
- 구독 기간, 가격, 자동 갱신, 복원, 해지 안내
- 최초 IAP는 앱 버전과 함께 제출해야 하는지 확인
- App Store Server Notifications 운영 환경과 sandbox URL

### 심사 정보

- 담당자 이름, 이메일, 전화번호
- 만료되지 않는 데모 계정
- 2FA를 막지 않는 심사 접근 방식
- 기능별 테스트 순서, 숨겨진 설정, 샘플 데이터
- QR, 스트림 URL, 외부 하드웨어, 데모 영상
- 심사 중 백엔드와 지원 인력 가용성

### 코드 걸림돌

- 회원가입이 있으면 앱 내부 계정 삭제
- 필요 없는 로그인 강제 금지
- 소셜 로그인과 동등 로그인 옵션
- UGC 필터·신고·차단·연락처
- 권한 거부 시 핵심 기능 전체가 불필요하게 중단되지 않음
- 테스트 광고, 개발 서버, 디버그 메뉴, 샘플 키 제거
- 개인정보·결제·의료·어린이·AI 기능의 실제 정책 구현
- 크래시, 빈 화면, 죽은 링크, placeholder, 미완성 버튼

### 바이너리와 릴리스 상태

- 프로젝트 지침에 따른 분석·단위·컴포넌트 테스트
- Release 컴파일 또는 archive 전 검증
- 최신 필수 Xcode·SDK 요구사항
- 앱 아이콘, launch asset, orientations, supported devices
- signing, provisioning, nested extension 서명
- 바이너리 크기, dSYM, symbol, privacy manifest 유효성
- `ARCHIVED`, `EXPORTED`, `UPLOADED`, `PROCESSING`, `PROCESSED`, `SUBMITTED`, `APPROVED`, `LIVE` 분리

## 4. 실제 거절 방지 점검

- 소스만 보고 동작 완료로 판정하지 않는다.
- 앱이 요구하는 모든 외부 서비스가 심사 중 작동하는지 확인한다.
- 메타데이터와 스크린샷이 현재 빌드에 없는 기능을 약속하지 않는지 확인한다.
- 정책 URL이 공개 접근 가능하고 앱 안에서도 열리는지 확인한다.
- 사용자 데이터 삭제 요청이 문서와 서버에서 실제로 처리되는지 확인한다.
- 앱이 수집하지 않는다고 답한 데이터가 SDK에서 전송되지 않는지 확인한다.
- archive 성공을 upload나 출시 완료로 부르지 않는다.

## 5. 완료 판정

`PREPARATION_COMPLETE`는 다음 조건을 모두 만족할 때만 사용한다.

- 안전하게 수행 가능한 조사·초안·코드 수정·헤드리스 검증을 완료했다.
- 모든 미확정 항목에 상태, 근거, 담당자, 다음 행동이 있다.
- `RELEASE_BLOCK`은 해결되었거나 구체적 재현 증거와 수정안이 있다.
- 사용자에게 받아야 할 값은 `FINAL_INPUT_REQUEST.md` 한 곳에 합쳐졌다.
- 포털 전용 작업은 정확한 화면과 입력값 단위로 정리되었다.
- 업로드·심사 제출·계약 동의·가격 확정은 권한 없이 실행하지 않았다.
