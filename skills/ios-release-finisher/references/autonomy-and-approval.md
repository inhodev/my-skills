# 자율 진행과 승인 경계

## 핵심 원칙

누락된 값은 곧바로 질문할 이유가 아니다. 그 값이 없으면 지금 수행하려는 안전한 작업 자체가 불가능한지를 먼저 판단한다.

## 계속 진행하는 항목

- 저장소와 프로젝트 지침 조사
- 코드·SDK·권한·데이터 흐름 감사
- App Store Connect 읽기와 차이 계산
- 개인정보 처리방침·약관·메타데이터 초안
- 연령 등급 후보와 근거 작성
- 이미지 촬영·현지화 계획
- 사용자가 요청한 출시 준비 범위의 코드 걸림돌 수정
- 정적 분석, 단위·컴포넌트 테스트, Release 컴파일 검증
- API 또는 포털 변경의 dry-run과 변경안 작성
- 누락된 사용자 값을 placeholder로 유지하고 다른 영역 진행

## 즉시 중단하지 않는 대표 누락값

- 공개 지원 이메일과 전화번호
- 개인정보 보호책임자 이름과 연락처
- 심사 담당자 연락처
- 가격과 기본 국가
- 출시 국가 목록
- 최종 카테고리
- 연령 등급의 사용자 승인
- 데모 계정 비밀번호
- 사업자등록번호, DSA trader 세부정보
- 최종 정책 URL

해당 값이 필요한 문서에는 명명된 placeholder를 두고, 사실관계와 본문을 먼저 완성한다.

## 해당 분기만 멈추는 항목

- 로그인과 2FA가 없어서 Apple 화면을 읽을 수 없음
- App Store Connect 권한이 없어 저장할 수 없음
- 계약 동의가 계정 소유자에게만 허용됨
- 인증서 private key 또는 signing team 선택이 필요함
- App Privacy `Publish`처럼 공개 API로 지원되지 않는 작업

이 경우 다른 로컬 작업, 문서, 코드 감사, 테스트를 계속한다.

## 전체 작업을 멈출 수 있는 조건

다음 중 하나이며 안전한 우회나 독립 작업이 더 없을 때만 질문한다.

1. 서로 다른 실제 앱 후보가 있어 잘못된 프로젝트를 수정할 위험이 있다.
2. 기존 사용자 변경과 직접 충돌하여 어느 쪽을 보존할지 결정할 수 없다.
3. 개인정보·콘텐츠·사업 사실을 임의로 만들지 않으면 다음 작업 자체를 진행할 수 없다.
4. 데이터 삭제, 계약 동의, 외부 공개, 결제, 업로드, 심사 제출처럼 새 권한이 필요하다.
5. 파괴적 또는 되돌리기 어려운 결정을 해야 한다.

질문은 하나만 한다. 왜 지금 반드시 필요한지와 멈춘 정확한 분기를 함께 적는다.

## 승인 정책

| 행동 | 기본 권한 |
|---|---|
| 읽기, 감사, 초안, dry-run | 계속 진행 |
| 사용자가 명시한 범위의 로컬 코드 수정 | 계속 진행 후 검증 |
| App Store 메타데이터 저장 | 변경 미리보기 후 현재 요청의 권한 확인 |
| App Privacy Publish | 사용자 확인과 포털 작업 |
| 계약, 세금, 은행, 법인 인증 | 계정 소유자가 직접 수행 |
| archive, upload, TestFlight 배포 | 현재 요청에 명시된 경우만 |
| App Review 제출, 출시 | 현재 요청에 명시된 경우만 |
| Made for Kids, 공개·비공개 배포 | 명시적 승인 필수 |

## 최종 입력 요청

모든 안전한 작업을 끝낸 다음 한 번만 요청한다. 각 항목에는 다음을 포함한다.

- 필요한 값
- 사용되는 위치
- 필수 또는 조건부 여부
- 비워 두면 생기는 영향
- 사용자가 그대로 복사해 답할 수 있는 형식

## 금지되는 조기 종료 문구

- “가격을 정해 주세요. 그다음 진행하겠습니다.”
- “이메일을 알려 주셔야 시작할 수 있습니다.”
- “연령 등급을 골라 주세요.”
- “개인정보 처리방침 URL이 없어서 더 진행할 수 없습니다.”

대신 수행 가능한 작업을 먼저 끝내고 `DEFERRED_INPUT`으로 기록한다.
