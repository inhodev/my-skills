# Ten-Screen Visual Contract

## Intake

Open all ten originals individually. Record filename, dimensions, visible state, selected navigation, content density, hero treatment, scroll extent, and every visible control. Images may arrive in arbitrary filename order; map by product flow, not lexicographic hope.

Separate four layers:

1. **System chrome:** device bezel and generated status/home indicators are reference context, not app assets.
2. **Product chrome:** tab bars, headers, sheets, navigation and persistent actions must be live UI.
3. **Content assets:** photos, portraits, 2.5D objects and illustrations may be bounded assets with clear provenance.
4. **Data visualization:** maps, charts, progress, timelines and world/game surfaces must be real views driven by model data, not cropped screenshots.

## Screen Map

For every screen record:

| Field | Required content |
|---|---|
| ID | stable `01` through `10` |
| Reference | absolute source path |
| Product state | route plus model/state fixture |
| Entry action | how a user reaches it from the real app |
| Primary action | visible effect and next state |
| Other controls | effect for every visible button, tab, filter, menu or toggle |
| KO capture | stable filename |
| EN capture | same state and stable filename |
| Boundaries | provider, permission, billing or device dependency |

The ten images are not ten disconnected pages. Connect them into the smallest coherent navigation and state graph that satisfies the product description.

## Fidelity Order

Fix mismatches in this order:

1. wrong screen/state/navigation;
2. missing signature composition or imagery;
3. hierarchy and information density;
4. typography and spacing rhythm;
5. color, elevation, corner and icon consistency;
6. decorative polish and motion.

Do not polish shadows while the screen structure is wrong.

## Token Rule

Create semantic tokens for repeated design decisions: roles, not reference coordinates. Include typography roles, spacing scale, radii, elevations, icon sizes, content widths, control heights, imagery aspect ratios, and screen-specific geometry names. A small named geometry file is acceptable for a signature illustration or map; raw layout numbers scattered across screens are not.

## Asset Integrity

Never use an original full-screen mockup, device screenshot, sliced text, button, card, map, chart, or tab bar as the app UI. Never place transparent controls over an image. Verify production sources contain no full-screen reference asset lookup.

Bounded photos or illustrations may be imported only for the matching content slot. Remove accidental device chrome from extracted content. If extraction quality or rights are uncertain, create a coherent placeholder and record it instead of faking provenance.

## Direct Visual Review

Open all originals and all fresh captures at useful scale. A montage helps compare rhythm but cannot prove text, CJK glyphs, clipping, selected states, or blank panels. Inspect those individually. Confirm the capture timestamp follows the latest relevant source change.
